## Runtime

Airflow runs on the private OCI services host with LocalExecutor, PostgreSQL metadata, a dedicated
DAG processor, scheduler, and triggerer. Completed task logs are stored in the KMS-encrypted S3 log
prefix with 30-day dev retention.

The official `GitDagBundle` loads `automation/airflow/bundle` by Git commit. Active and retried runs
keep their original bundle version. A DAG-only change therefore needs bundle validation, not a new
Airflow image.

There is no OCR DAG. OCR is an explicit local CLI action backed by Modal.

## DAG naming

```text
<job_type>_<worker_type>_<verb>_<scope>
```

The bounded vocabulary and examples are in [Conventions](/docs/reference/conventions). The primary
publication runtime belongs in `worker_type`; supporting runtimes are explicit task boundaries and
DAG tags. `scope` describes stable business or data ownership. Existing DAG IDs stay stable so
deployments preserve run history.

## Execution boundaries

- External-source capture tasks use the shared immutable `lakehouse-ingest` image and its
  raw-prefix-only workload identity.
- EMR tasks consume terminal S3 manifests, use deterministic client tokens, and cancel remotely on
  kill.
- dbt tasks use the shared immutable image but mount a domain-specific Roles Anywhere identity.
- Airflow records logical asset success only after the producer succeeds.
- Slack and SMTP notifications use Airflow connections loaded from Secrets Manager.
- Airflow itself has no landing, curated, or analytics data permission.

## Historical runs

GitHub Archive and ArXiv metadata use explicit T-1 partition timetables; SSI REST uses its same-day
trade-date partition. Manual source runs default to the latest completed UTC day. Use Airflow 3's
Backfill action for a date range instead of passing a custom date Param or maintaining a second DAG.
Keep `catchup=False`: the scheduler processes only the latest partition automatically, while an
explicit backfill controls historical creation with `none`, `failed`, or `completed` reprocessing
behavior and its own concurrency limit.

Use `none` to fill missing dates, `failed` after repairing a failed workflow, and `completed` only
when intentionally replaying an already completed partition. GitHub Archive and ArXiv capture
manifests are first-writer-wins: a successful rerun reuses the committed raw capture rather than
silently observing the source again. Preview the range with the Backfill dry-run before a large
request and keep source backfills at one active run unless the upstream API has been capacity-tested.

The stream replay DAG discovers existing immutable terminal manifests for each partition date.
Native backfill can therefore repair or republish captured raw sessions, but it cannot reconstruct a
market session that the OCI capture service never recorded. Iceberg maintenance operates on current
table state, and analytics is asset-triggered; both are rerun directly rather than historically
backfilled.

## Operations

```bash
make airflow-up
make airflow-dags
make airflow-logs
```

If no DAG appears, inspect DAG processor and scheduler logs separately, confirm the bundle commit is
reachable, then list parsed DAGs with `make airflow-dags`.
