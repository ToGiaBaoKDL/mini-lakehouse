## Structure

```text
analytics/
├── dbt-project/
│   └── models/
│       ├── sources/
│       ├── staging/
│       ├── intermediate/
│       └── marts/
└── lightdash/
    ├── project/
    └── deploy/
```

One dbt project owns three domains. `engineering` selects GitHub-derived models, `research` selects
ArXiv-derived models, and `trading` selects certified market-research models. Staging and
intermediate models are ephemeral. Marts default to physical Iceberg tables in
`analytics_engineering`, `analytics_research`, and `analytics_trading`; the Trading backtest mart is
an intentional view so a failed source certification is excluded immediately.

The current project-level mart materialization is `table`: a dbt run replaces each selected logical
mart. The Athena adapter owns the physical table location within the domain's analytics prefix.
Source YAML contains only dbt mappings, freshness policy, and source tests; the platform contract
remains the canonical curated schema.

## Execution

```bash
make dbt-deps
make dbt-validate
make dbt-build DBT_DOMAIN=engineering
make dbt-build DBT_DOMAIN=research
make dbt-build DBT_DOMAIN=trading
```

The domains share an image but use separate Roles Anywhere identities, Glue databases, S3
prefixes, and Athena query-result prefixes. Airflow runs them through one analytics DAG.

## Lightdash

The `Lakehouse Analytics` Lightdash project consumes all three analytics databases through Athena.
Git owns its Engineering, Research, and Trading spaces, charts, and dashboards under
`analytics/lightdash/project/content`. UI-authored content must live outside those managed spaces.
Athena evaluates stored views with the caller's permissions, so Lightdash additionally has read-only
access to the exact `curated_t0_trading` database and `t0_trading` object prefix underlying the
certification-gated Trading view.

```bash
make lightdash-validate
```

The protected workflow compiles the complete dbt manifest, deploys one semantic layer, uploads the
managed content, and validates the project. Lightdash has its own image, database, secrets, and
release lifecycle even though it shares Analytics ownership with dbt.
