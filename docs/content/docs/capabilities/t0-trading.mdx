---
title: T0 Trading
description: An evidence-gated SSI market-data and assisted-decision capability.
---

T0 Trading has a catalog foundation, a scheduled bounded REST publication path, weekday live stream
capture, manifest-scoped replay, and deterministic offline/shadow decisions. Shadow output remains
a journal: the capability does not send notifications, initialize an SSI trading client, or place
broker orders.

## Provider boundary

The capability uses `ssi-sdk` 3.2.1 for authentication, Data REST calls, streaming connections, and
subscriptions. Stream capture sends periodic SDK-owned heartbeat pings and fails closed when their
responses become stale. Application code does not reproduce SSI endpoints, retry logic, or protocol
messages. The pinned SDK recognizes `market.*` messages but omits a public market-status subscription
helper, so one narrow adapter owns that documented topic boundary. Certification uses only the Data
and Stream DATA clients.

In the pinned SDK, `subscribe_board` remains a convenience subscription for board-wide trade, quote,
and foreign-room topics. Market phase is captured separately from the official `market.HOSE`
stream. A successful subscription acknowledgement without business messages still cannot prove an
exchange trading date, so completed-date REST publication continues to use the independently
observed trading-date resolver.

Terraform owns the empty SSI and PostgreSQL secret containers, an immutable ECR repository, and a
dedicated Roles Anywhere identity. The capture runtime can read only the SSI credential and landing
URI parameter, and can read or write only the SSI REST and Stream raw prefixes. It has no
operational-ledger, Glue, or curated-table permissions.

## Data contracts

`landing_ssi_fastconnect_rest` and `landing_ssi_fastconnect_stream` preserve canonical SDK records
with request/session, object, checksum, and publication lineage. A local stream receive sequence
records callback order but is never represented as a provider event identifier.

`curated_market_data` owns effective-dated securities, revision-preserving daily summaries and
one-minute bars, at-least-once trade ticks, quote snapshots and levels, index snapshots, market
status events, and structured corporate actions. Every decision-relevant fact separates event,
receipt, availability, and processing time where the source permits it. Prices and monetary values
use explicit decimal precision and scale through Pydantic, PyIceberg, and Spark; quantities and
sequences remain integers. Live and historical bars converge into one table through source and
revision lineage.

`market_status_events` and `corporate_actions` are structured facts, not news or sentiment feeds.
Market-level status now has an official stream writer. Symbol-level SSI `F` security status is not
exposed by pinned `ssi-sdk` 3.2.1, so symbol halt/suspension remains protected by the existing
trade/quote freshness abstention rather than being misrepresented as a certified status event.
Corporate actions remain empty until an official structured source is certified.

The physical tables intentionally use one table per durable grain, not one table per engine:

| Tables                                                                          | State                            | Reason                                                                                    |
| ------------------------------------------------------------------------------- | -------------------------------- | ----------------------------------------------------------------------------------------- |
| REST `records`, `request_publications`                                          | Active in bounded publication    | Immutable records and one terminal request marker are different grains.                   |
| `securities`, `daily_security_summaries`, `intraday_bars_1m`, `index_snapshots` | Active in bounded publication    | Current certified REST normalization output.                                              |
| Stream `messages`, `sessions`                                                   | Active in manifest-scoped replay | Message lineage and terminal connection-session completeness are the two durable grains.  |
| `trade_ticks`, `quote_snapshots`, `quote_levels`                                | Active in manifest-scoped replay | Quotes use a parent snapshot plus one-to-many levels; ticks retain receive order.         |
| `market_status_events`                                                          | Active in manifest-scoped replay | Official market-phase transitions feed the point-in-time fail-closed context gate.        |
| `corporate_actions`                                                             | Deferred                         | Required for adjusted replay, but has no writer until its structured source is certified. |

Each bounded EMR job requires only the landing and curated tables that it writes. Deferred
contracts do not add a runtime branch, generic repository, or empty application service.

## Deterministic market state

`t0-trading/config/trading.yaml` is the single non-secret configuration document. Strict Pydantic
models reject unknown fields, invalid effective intervals, duplicate identifiers, and unsupported
market-state settings. The canonical document and each selected effective policy have a stable
SHA-256 identity. Decision thresholds are isolated from feature, score, outcome, and evaluation
identities. The initial thresholds are explicitly provisional shadow settings derived from an
in-sample score profile; they cannot authorize advisory or live execution.

The top-level `capture` scope is operational evidence policy, not a model input. It currently
captures `VIC`, `VHM`, `VNINDEX`, `VN30`, and `VNREAL`; every effective market version must be
covered by that scope. The effective market version keeps `VNINDEX` and `VN30` as the required
regime inputs, so missing optional `VNREAL` evidence cannot turn the regime into `UNKNOWN`.
Changing the capture scope therefore does not change an existing feature-configuration identity.

The side-effect-free `t0_trading.market` package owns three boundaries: decoding persisted SDK
messages into the certified event subset, deterministic market-state transitions, and ordered
replay through those same transitions. It maintains bounded latest trade/Top-3 quote state and
trade-built one-minute bars using exact decimal arithmetic. Sequence gaps, receipt/event-time
regressions, late trades, incomplete quotes, stale data, and values unavailable at the evaluation
time fail closed. Auction observations remain distinct from executable trades and do not create
synthetic bars.

Configuration can be validated without AWS or SSI access:

```bash
uv run t0-trading check-config \
  --config t0-trading/config/trading.yaml \
  --effective-date 2026-09-05
```

The side-effect-free `t0_trading.features` package builds on that state boundary. Its effective
configuration owns a five-second cadence, 30/60/300-second trailing windows, a 300-second warm-up,
and the continuous sessions in which a snapshot may become eligible. It emits one immutable,
versioned `FeatureSnapshot` per configured symbol and decision instant. Every snapshot carries its
configuration hash, raw stream watermark, observation ages, and explicit fail-closed reasons.

Feature calculations are deliberately limited to facts supported by the certified SSI feed:

- Top-3 depth, spread, midpoint, weighted microprice, and depth imbalance;
- Level-1 quote-transition order-flow imbalance without inventing order IDs or cancellations;
- signed trade flow, VWAP, return, and realized volatility over each configured window; and
- receipt-time freshness, session-local warm-up, and minimum-observation gates.

The incremental live clock and full-session replay call the same `FeatureEngine`. Golden tests
compare their complete snapshot contracts and prove that an observation received after a decision
instant cannot alter that decision's features. The engine retains only the largest configured
window per symbol; it does not introduce a dataframe runtime or generic feature-store abstraction
for this two-symbol hot path.

A certified market day can be audited locally without publishing snapshots or creating another S3
artifact. The command discovers and certifies all reconnect segments before replay. Its stable JSON
report reconciles every configured decision key exactly once and
summarizes eligible coverage, fail-closed reasons, full-clock null rates, and numeric distributions
from eligible snapshots by symbol, session, and window:

```bash
AWS_PROFILE=tgbao-dev uv run --project t0-trading t0-trading audit-features \
  --trade-date YYYY-MM-DD \
  --landing-uri s3://<landing-bucket> \
  --output /tmp/t0-feature-audit.json
```

The audit exhausts the logical-day reader, so the end of the continuous feature clock cannot skip
terminal batch, checksum, sequence, or reconnect-gap validation for closing-auction messages.

The scheduled stream publication uses that same engine after the certified landing merge. EMR
loads the `trading.yaml` artifact from its own immutable code release, orders the complete landing
session by capture sequence, runs the feature audit, and then idempotently merges tables owned
by `curated_t0_trading`:

- `market_day_certifications` is the current deterministic backtest-eligibility decision for one
  trade date and configuration SHA, including the immutable manifest-set hash and failure reason;
- `feature_snapshots` has one row per feature version, configuration SHA, symbol, and decision
  instant, including source position, eligibility, reasons, availability, and immutable hashes;
- `feature_windows` has one child row per configured trailing window, avoiding hard-coded
  `30s`/`60s`/`300s` columns as later effective versions add or remove windows;
- `outcome_labels` has one immutable conditional Top-3 markout per outcome policy, feature
  snapshot, action, and horizon;
- `decision_contexts` stores the versioned zone, index-window, market-confirmation, and regime
  result at each feature clock. `data_mode` distinguishes genuine `LIVE` evidence from an explicit
  completed-day `HISTORICAL_PROXY`;
- `strategy_candidates` stores the complete buy-first candidate/abstention matrix, including every
  evidence group, block reason, and feature/context fingerprint;
- `strategy_evaluations` stores overall and regime-sliced conditional gross and public-DTA-cost
  results with capture, feature, context, outcome, and cost-policy lineage;
- `shadow_decisions` has one immutable strategy decision per decision policy and feature snapshot,
  including score lineage, applied threshold, action, and structured abstention reasons. It is
  reconstructed research evidence, not proof of notification delivery or order execution.

All snapshots, including deliberate abstentions during warm-up or sparse trading, are retained for
leakage-safe research. `processed_at` records replay publication time, while `available_at` remains
the original decision instant. The capture service cannot write these Iceberg tables; EMR remains
the sole landing and curated mutation owner.

This core has no S3, database, notification, or broker side effects. Replay invokes it explicitly;
the capture service remains responsible only for lossless raw evidence and SDK callbacks perform
only a non-blocking queue write. The shadow decision engine consumes the same incremental snapshots
without adding another provider callback. dbt remains the downstream analytics owner and does not
reimplement market-state or point-in-time feature transitions.

## Offline outcome labels

The side-effect-free `t0_trading.outcomes` package evaluates conditional Top-3 taker markouts from
the same certified stream. Outcome assumptions are effective-versioned separately in
`trading.yaml`, so changing a research horizon, order quantity, or latency scenario cannot change
the identity of an existing feature snapshot. The initial policy evaluates 30/60/300-second
horizons for one 100-share scenario with an explicitly assumed 500-millisecond routing latency.
That latency is a research scenario, not a measured SSI order-routing guarantee.

For each feature snapshot, action, and horizon, the simulator selects only the latest quote whose
receipt time is no later than the simulated entry or horizon clock. It walks the visible Top-3 book
to a full-quantity VWAP and fails closed on a missing, incomplete, stale, or insufficient-depth
book. Quote selection reuses the same `MarketState` replay as feature generation, so sequence,
receipt-time, and provider-event-time regressions cannot diverge between features and labels. Both
receipt age and provider event age must satisfy the configured quote-freshness policy. A horizon
that reaches lunch, an auction, or the end of its continuous session is excluded. Golden tests
prove that a quote received after the horizon cannot change the earlier label.

The offline audit runs the same verified session through feature replay and outcome labeling without
publishing either dataset:

```bash
AWS_PROFILE=tgbao-dev uv run --project t0-trading t0-trading audit-outcomes \
  --trade-date YYYY-MM-DD \
  --landing-uri s3://<landing-bucket> \
  --output /tmp/t0-outcome-audit.json
```

It validates the complete snapshot/action/horizon matrix and reports eligibility, entry and horizon
fill rates, reason counts, positive/negative gross-markout rates, and p05/p50/p95 distributions per
symbol, direction, and horizon. `worst_observed_markout_bps` is the worst configured-horizon return
for paths eligible at every horizon; it is intentionally not named maximum adverse excursion because
the simulator does not observe a continuous execution path. The paired BUY+SELL summary makes
directional asymmetry and visible-book crossing cost explicit without inventing fees or fills.

`BUY` measures a marketable buy followed by a conditional bid-side markout; `SELL` measures a sale
of already-settled inventory followed by a conditional ask-side repurchase. These are gross
research markouts, not claimed broker fills or executable round trips. They neither bypass Vietnam
settlement constraints nor include an invented commission or tax schedule. Operational Net PnL and
portfolio eligibility remain unavailable until account-specific cost and inventory inputs are
verified and prospective execution is measured. For a certified day, EMR publishes the complete label matrix with quote-sequence
lineage, structured abstention reasons, and a canonical fingerprint. It remains research data and
is not consumed by signal generation.

## Offline T0 cycle simulation

The research-only `t0_trading.simulation` package adds deterministic cash and inventory accounting
without changing capture, curated tables, or the shadow decision clock. It accepts a single-day
`SimulationRequest` containing an explicitly selected set of exact decision/outcome pairs, a
timestamped manual account snapshot, per-symbol closing marks, effective-dated VND cost assumptions,
and explicit risk limits. The caller owns candidate arbitration and supplies one `SelectionRecord`
per selected decision from a decision-only journal, timestamped after the decision but before its
simulated entry. The simulator checks identity and priority and rejects two candidates for the same
symbol and decision clock. The source digest and timestamp are supplied evidence, **not** proof
that an external journal was committed before outcomes existed. Promotion requires an independently
immutable journal and a completeness audit of the candidate universe. The request also supplies
the lot size; a quantity outside the lot is rejected before accounting.

For `BUY_LOW_SELL_OLD`, the first leg consumes cash and the later sale consumes previously settled
shares. For `SELL_HIGH_BUY_BACK`, the first leg consumes settled shares and the later repurchase
creates shares bought today. Both paths preserve `core_min_qty`; bought-today shares are never
reused as settled inventory. Commission and sell tax apply to their respective legs, while optional
extra slippage is added **after** the visible Top-3 VWAP, so spread crossing is not charged twice.
Sale proceeds enter `pending_sale_proceeds_vnd`, not spendable cash. Without an `AdvancePolicy`, a
sell-first buyback must use existing cash. An explicitly configured advance may fund buys only
against unadvanced pending proceeds after projected interest through the supplied settlement date.
The input `account.cash_vnd` must therefore be settled available cash, not a broker-app buying-power
figure that already includes pending sales or financing.
The report exposes cash, receivables, advance principal, and financing cost separately; aggregate
Net T0 Alpha deducts financing cost. This is an estimate, not confirmation that the account has
enabled the advance service.
The report compares the same initial holdings under HOLD and HOLD+T0, with Net T0 Alpha equal to
the incremental portfolio P&L of completed cycles. It carries an input fingerprint and one `cycle_id`
per selected decision. An unfillable exit leaves the account open and withholds aggregate Net T0
Alpha rather than inventing a repurchase or sale. Account `start_price` and the closing mark only
value the common HOLD inventory; they do not create synthetic opening or closing fills.

```bash
uv run --project t0-trading t0-trading simulate-cycles \
  --input /path/to/selected-cycle-request.json \
  --output /tmp/t0-cycle-report.json
```

The JSON contract is `SimulationRequest` in `t0_trading.simulation.model`; it requires the full
immutable `StrategyDecision` and `OutcomeLabel` records, not bare prices or a profit estimate.
`COMPLETE` means the accounting reconciles, **not** that a strategy passed research or is ready
for a user alert. For the confirmed VNDIRECT DTA account, `public_vndirect_dta_costs` provides an
explicit `PUBLIC_SCHEDULE_ASSUMPTION`: 10 bps online brokerage on each side and 10 bps tax on sales,
based on the [DTA schedule](https://www.vndirect.com.vn/bieu-phi-tai-khoan-da/) and
[VNDIRECT tax guidance](https://support.vndirect.com.vn/hc/vi/articles/14623187438873).
Pages checked on 2026-09-22 do not prove the account's negotiated rate or an earlier historical
rate. Any additional tax treatment of dividend or bonus shares is outside this ordinary-sale
scenario. `fee_provenance_recorded` means a source and check timestamp were provided, not that the
tariff was independently verified. Likewise, `selection_reference_recorded` means selection
references were supplied, not independently authenticated. The public
[sale-proceeds advance page](https://www.vndirect.com.vn/dich-vu-chung-khoan/san-pham-dich-vu/margin/ung-truoc-tien-ban-uttb/)
shows 3.7 bps per calendar day; this is a separate, opt-in assumption. An incomplete report is
emitted and the CLI exits with the data-quality code. Current outcome labels still use the
configured 500 ms research-latency scenario and 100-share marketable Top-3 book walk, not observed
human response times or broker fills. A separate, measured manual-latency policy and prospective
paper journal remain mandatory before any promotion decision. Tick/price-limit validation and
passive-order queue or partial-fill simulation are not inferred from aggregate Top-3 VWAP labels.

## Offline strategy scores

The side-effect-free `t0_trading.strategy` package derives three threshold-free research scores
directly from eligible `FeatureSnapshot` objects: volatility-normalized momentum confirmed by trade
flow, normalized order flow and book imbalance, and a symmetric VIC/VHM relative-value score. Each
score is bounded to `[-1, 1]`, uses exact decimal arithmetic, and carries the feature snapshot and
effective strategy-policy fingerprints. Its sign selects the matching conditional BUY or SELL
outcome only for evaluation; it is not an order, signal, or execution instruction.

### Buy-first brief baselines

The separate `strategy.baselines` research path does not alter the deployed shadow decision policy.
It evaluates the three hypotheses from the project brief for BUY-first cycles only. Baseline v3
joins a separately versioned, immutable `DecisionContext` at the exact feature clock:

- Mean Reversion requires a below-VWAP price stretch, proximity to support, and a matching reversal
  confirmation. Its zone is the support/resistance range over prior eligible snapshots in the
  configured trailing window; the current clock and future pivots cannot define their own zone.
- Momentum/Pullback requires positive 60/300-second trend strength and either a controlled
  30-second pullback with positive trade flow or 30-second reacceleration. These are intentionally
  minimal baseline proxies, not tuned final thresholds.
- VIC–VHM Relative requires target underperformance, a prior disjoint 30-second peer move followed
  by target recovery, and positive broad-market confirmation. The lagged move is a baseline proxy,
  not a fitted rolling leader model. Positive VN30 and VNINDEX returns confirm the candidate only
  when both index streams are fresh and have complete point-in-time lookback windows.

The same context classifies `TREND_UP`, `TREND_DOWN`, `RANGE`, or `HIGH_VOLATILITY` from VNINDEX and
VN30. Live publication prefers index stream observations. For pre-index-stream dates, research replay
may use completed-day one-minute REST bars, but records `HISTORICAL_PROXY` and the original REST
record hash on every context; it never presents those bars as contemporaneously received stream
evidence. A REST close is conservatively exposed only after one complete configured bar interval;
both that delay and its staleness grace are versioned in the context-policy hash. Missing, stale, or
insufficient history produces `UNKNOWN` with explicit reasons. A daily
index summary is never expanded into synthetic intraday observations. Context policy, source feature
history, source lineage, and the resulting snapshot each carry independent hashes. Regime performance
is reported as a segment, not used as a threshold tuned on the evaluated sessions.

Live context also requires the latest received HOSE market phase to be one of the versioned
tradable statuses. Market status is a transition state and remains effective until another
transition; it is not incorrectly expired by a telemetry TTL. Missing status, `BREAK`, `HALT`, or
another disallowed phase makes the context `UNKNOWN` and blocks all three baselines before candidate
selection. Historical proxy analysis records a separate configured-calendar source and never claims
that it observed a live status transition.

Every feature clock emits all three group states and either a research candidate or an explicit
abstention. Scoring reads only feature snapshots at or before the decision clock; the outcome is
joined later using the immutable snapshot hash. The audit selects the first candidate after a
cooldown equal to the longest outcome horizon, independently for each strategy and symbol, so
overlapping five-second clocks are not counted as separate trades. It reports group availability,
raw and non-overlapping candidate counts, outcome coverage, gross markout, and conditional net
markout after the public DTA fee/tax assumption:

```bash
AWS_PROFILE=tgbao-dev uv run --project t0-trading t0-trading audit-buy-first-baselines \
  --trade-date YYYY-MM-DD \
  --landing-uri s3://<landing-bucket> \
  --output /tmp/t0-buy-first-baselines-YYYY-MM-DD.json
```

The public DTA schedule was checked on 2026-09-22; applying it to an earlier date is explicitly a
historical research assumption. Even the fee-adjusted result is a **conditional Top-3 markout**, not
portfolio Net T0 Alpha: the baseline audit does not arbitrate simultaneous strategies, reserve
cash, enforce core inventory, observe broker fills, or prove that the brief's missing regime/news
groups were available. It must not be promoted to Telegram or manual trade guidance on this report
alone.

## Offline and shadow decisions

The `t0_trading.decisions` package turns each candidate strategy score into `BUY`, `SELL`, or
`ABSTAIN` using an effective-dated policy. Momentum, order-flow, and relative-value remain separate
candidates; the engine does not manufacture an ensemble before out-of-sample evidence exists.
Directional thresholds are independent for each side. Shared fail-closed gates limit quoted spread,
trade age, quote age, and repeated decisions during a per-strategy cooldown.

Offline replay and a shadow clock call the same stateful `DecisionEngine`. Mode is deliberately not
part of decision identity: it controls the input and sink, not the formula. A golden test advances
the live feature and decision clocks over captured envelopes and compares every immutable decision
with full replay. The replay CLI discovers all terminal segments for a certified trade date and
writes canonical JSON Lines without notification or broker side effects:

```bash
AWS_PROFILE=tgbao-dev uv run --project t0-trading t0-trading journal-decisions \
  --trade-date YYYY-MM-DD \
  --landing-uri s3://<landing-bucket> \
  --output /tmp/t0-decisions-YYYY-MM-DD.jsonl
```

The command prints action counts and a SHA-256 for the complete journal. Replaying the same immutable
capture and policy produces byte-identical output. These records remain shadow research evidence;
notification routing, user acknowledgement, inventory checks, and broker execution belong to later
advisory and live lifecycles.

The scheduled capture container also writes local decision and baseline-candidate journals from the receipt-ordered queue,
outside the SSI SDK callback. Its clock stays one feature cadence behind receipt time to avoid racing
callback delivery. A reconnect is recorded as `CAPTURE_GAP` through the configured warm-up period.
During processing, the file remains `.jsonl.partial`. A bounded shutdown publishes the journal and
then a sidecar `.manifest.json` as its commit marker only when capture began before the first decision
clock, every configured clock was evaluated, and every observed stream session has a terminal S3
capture manifest for the same trade date. The sidecar owns decision, context, baseline, session,
count, and checksum lineage; consumers ignore partial files or journals without the manifest. The
`.candidates.jsonl` artifact contains all three baseline outcomes—including abstentions—for every
symbol and clock. Shadow
initialization, processing, or reporting errors disable only the journal; immutable raw capture
remains the primary workload and continues independently. The local journal is parity evidence, not
a serving database or notification queue. Completed local artifacts are retained for 14 days and
partial artifacts for three days; cleanup runs before the scheduled capture opens a new journal.

Audit a committed local journal against the exact terminal capture lineage declared by its manifest:

```bash
uv run --project t0-trading t0-trading audit-shadow-journal \
  --manifest /path/to/YYYY-MM-DDTHHMMSS.ffffffZ.manifest.json
```

The audit validates canonical local artifacts, effective policy hashes, the complete decision clock,
every S3 manifest and batch checksum, receipt ordering, capture gaps, decision counts, and finally
compares every journal record byte-for-byte with deterministic replay. It is read-only and exits
non-zero on any mismatch.

dbt exposes `analytics_trading.fct_trading_backtest_observations` as a safe-by-default view. It
inner joins the current passed certification, eligible snapshots, their normalized windows, and
eligible outcomes using their existing immutable lineage. The view does not rederive market state,
features, coverage, or returns, and failed certifications disappear immediately without an
incremental-delete repair path.

`analytics_trading.fct_trading_shadow_decision_outcomes` keeps one row per deterministic decision
and left joins its exact policy, snapshot, direction, and horizon to the conditional outcome. This
preserves ABSTAIN decisions and failed outcome-quality gates instead of silently selecting only
successful simulations. The Lightdash shadow-decision dashboard separates action rate, eligible
outcome coverage, positive gross markouts, and mean eligible gross return so missing markouts are
never treated as zero returns.

The bounded stream command subscribes to aggregate symbol data and one-minute intervals for
`VIC,VHM`, plus the captured `VNINDEX,VN30,VNREAL` index stream and HOSE market-status transitions.
Stream manifest v3 records symbol, index, and market scopes, while replay remains backward compatible
with v1/v2 manifests.
Landing validates each non-null identifier against its declared scope. Curated replay routes only
symbol-scoped trades and quotes into security tables; index-scoped trade observations are published
idempotently to `index_snapshots` with their receipt-time lineage. SDK callbacks only serialize
into a bounded in-memory queue; the main process writes
content-addressed gzip micro-batches every 30 seconds or 500 messages, whichever comes first, so S3
latency cannot block the WebSocket receive thread. Each
terminal session manifest owns batch/object checksums, sequence bounds, heartbeat health, and the
disconnect classification. Replay enriches landing messages with that manifest lineage; a separate
batch-publication table would repeat the same fact and is intentionally absent.

The deployed canary established the concrete callback shapes used by replay:

| SDK callback          | Certified shape                                                     | Replay destination                                                                   |
| --------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `TradeMessage`        | Symbol, provider time, price, quantity, side, and cumulative volume | Symbol-scoped executable matches go to `trade_ticks`; auction state stays in landing |
| Index `TradeMessage`  | Index code, provider time, value, and cumulative market volume      | Index-scoped observations go to `index_snapshots`                                    |
| `QuoteMessage`        | Ten price/quantity slots with the advertised Top 3 populated        | `quote_snapshots` and `quote_levels`                                                 |
| `IntervalMessage`     | Provider one-minute OHLCV observation                               | Landing evidence for later reconciliation                                            |
| `ForeignRoomMessage`  | Cumulative foreign flow and room observation                        | Landing evidence; not a final daily fact                                             |
| `MarketStatusMessage` | HOSE phase and provider trading date                                | `market_status_events` and the live fail-closed context gate                         |
| `dict`                | DATA-channel subscription acknowledgement                           | Landing evidence only                                                                |

Replay does not turn interval observations into authoritative bars or partial foreign-room updates
into final daily summaries. Completed-day REST bars remain the published authoritative path. A
streaming reader now verifies and rebuilds deterministic trade bars for full-session certification;
promotion of those bars into curated storage remains a separate delivery gate.

The capture process handles `SIGTERM`/`SIGINT`, disconnects through the SDK, drains its queue, and
writes the terminal manifest. Every batch is atomically fsynced into a bounded local outbox before
delivery. Transport, throttling, and server-side S3 failures leave the batch in place while capture
continues and later flushes retry delivery; permission errors, immutable conflicts, local corruption,
and a full spool still fail immediately. The terminal manifest is delivered only after its batches.

The weekday capture is intentionally immutable for the whole market-data window. A deployment
during that window is refused before stopping or replacing the active container; it must be rerun
before 08:30 or after 15:40 local time. This prevents a release from splitting the day into multiple
partial sessions that cannot pass full-session certification.

## Bounded publication

The `etl_mix_ingest_market_data_rest` DAG uses Airflow 3's daily partition timetable at 17:00 Monday
through Friday in `Asia/Ho_Chi_Minh`. Its partition key is the exact exchange-local trade date used
by capture and publication. Historical ranges use Airflow's native Backfill action; there is no
date Param, resolver task, or separate backfill DAG.

Capture rejects future dates and asks SSI for the exact VN30 historical date before writing raw
evidence. A weekday with no SSI-observed session exits through DockerOperator's supported skip code,
so exchange holidays do not create empty captures. Backfills and scheduled runs therefore share the
same bounded data-readiness rule without branching on the Airflow run type.

The publication flow is:

1. the `t0-trading` image composes official Data SDK calls and writes content-addressed, gzipped
   records plus checksum manifests below the SSI REST source prefix;
2. the EMR job validates the exact request scope, SDK/API compatibility, timestamp order, object and
   request counts, object metadata, model types, record hashes, and duplicate keys before
   append-only landing publication;
3. EMR publishes effective-dated securities and revision-preserving daily, one-minute, and index
   facts only after date/symbol scope and OHLC reconciliation checks pass. SSI all-zero minute
   placeholders are omitted; zero sentinels inside a positive-volume auction bar are normalized
   from its positive close while the immutable source record remains unchanged in landing.

An Airflow retry reuses the same capture manifest. A new DAG run creates a new raw observation, but
unchanged curated source fingerprints do not create another revision. Historical REST index
summaries retain a null `event_time` because the SDK supplies a date but no event timestamp; the
pipeline does not invent a market-close time.

Each bounded capture stays below one deterministic source-owned boundary:
`api/ssi_fastconnect_rest/raw/trade_date=<date>/run=<token-sha256-prefix>/`. Landing and curated
Iceberg data use the catalog-wide `tables/<table>/` namespace; capture code never constructs those
table locations.

## Stream replay

The OCI services host runs the capture container from 08:30 until 15:40, Monday through Friday, in
`Asia/Ho_Chi_Minh`. Component-owned systemd timers own this lifecycle; a persistent start timer can
recover a host reboot during the window, while a local-time guard prevents a missed start from
running after 15:40. The stop timer sends a graceful termination so the capture flushes its final
micro-batch and terminal manifest. Image deployment recreates the container and converges it to the
schedule's desired state outside the capture window. Deployment inside the window is refused before
the running container is touched, preserving the single full-session invariant.

That 08:30–15:40 lifecycle is intentionally a conservative evidence-capture window, not a trading
or signal window. The effective-dated session clock in `trading.yaml` is the semantic source of
truth: it classifies ATO, continuous trading, lunch, ATC, and closed periods independently of the
container lifecycle. SSI stamps closing-auction executions at exactly 14:45:00, so that boundary is
included in ATC; later timestamps are closed. The 15:40 stop retains the provider activity observed
through roughly 15:32 in certified sessions; stopping at 15:30 would discard that evidence for no
meaningful resource saving.

The timer excludes weekends but does not pretend to know ad-hoc HOSE holidays. Until a structured
exchange-calendar source is certified, a weekday holiday is captured conservatively: SDK
heartbeats and acknowledgements remain as immutable raw evidence. The 17:00 certification uses SSI's
exact-date history and skips lakehouse publication, so it cannot create synthetic landing or curated
facts for that date.

At 17:00 Monday through Friday, `etl_emr_ingest_market_data_stream` first runs a bounded manifest
validation task. It uses SSI's exact-date history through the official SDK as the trading-day gate;
an unobserved date exits with the shared Airflow skip code. For an observed date it discovers every
direct terminal manifest and validates its immutable lineage before submitting EMR.

The EMR job independently validates every batch and publishes structurally valid sessions to
landing and curated market-data tables even when reconnects make the day unsuitable for research.
It then upserts `market_day_certifications` from the complete manifest set. Exactly one session must
cover the configured market window and symbol scope for status `passed`; otherwise the job records
the stable failure reason and withholds all feature snapshots, windows, and outcomes. The final Airflow task
reruns the shared reconciliation. An ineligible day uses the dedicated data-quality exit code, so
Airflow marks that task skipped, keeps the completed DAG run successful, and sends a warning through
the standard Slack and email routes. Configuration, AWS, checksum, schema, and replay failures remain
technical failures and fail the DAG. This preserves an operational signal without discarding valid
evidence or reporting a successful publication as broken infrastructure.

Each session must pass manifest checksum, terminal-kind/error consistency, heartbeat, SDK/API
version, contiguous sequence, batch identity, object location, record-count, message-hash,
timestamp, and duplicate-key validation. A transport failure after a session has already covered
market close remains explicit evidence and does not invalidate the completed market window; the
same failure before market close cannot satisfy coverage and fails feature eligibility.

Landing publication merges `messages` by `(stream_session_id, receive_sequence)` and writes the
terminal `sessions` row last, including its sanitized `error_type` when present. Curated publication
maps positive-price, positive-quantity
`TradeMessage` records with a buy or sell side into `trade_ticks`. SSI auction-state observations
with zero price, zero quantity, and unknown side remain available in landing without becoming
synthetic trades. Any other malformed combination fails closed. Certified `QuoteMessage` records
populate snapshots and levels. Retries reuse the same manifest and insert no duplicates; a
conflicting manifest, message, tick, snapshot, feature, window, or outcome fails closed.

Offline feature and outcome audits use the same eligibility selector and therefore reject captures
without full-session coverage. The dbt backtest view inner joins `market_day_certifications` on
trade date, configuration SHA, and selected session with `status = 'passed'`; dbt does not rederive
capture coverage from ticks or quotes. This distinguishes a genuinely quiet market from a day whose
data is missing.

The same terminal manifest can be audited independently of Spark. The reader verifies checksum
metadata, manifest and batch lineage, SDK/API versions, contiguous receipt sequence, row schema,
payload hashes, publication order, publication-after-receipt causality, terminal receipt time, and
the shared 10,000-message batch ceiling while yielding one gzip batch at a time. A bounded
eight-object prefetch window reduces S3 latency without changing receipt order or loading the full
session into memory. The reconciliation command then runs the production market-state transitions,
classifies events using the effective-dated session clock in `trading.yaml`, and compares trade-built
minute bars with SSI's rolling interval observations:

```bash
AWS_PROFILE=tgbao-dev uv run --project t0-trading t0-trading reconcile-stream \
  --manifest-uri 's3://<landing-bucket>/stream/ssi_fastconnect_stream/raw/trade_date=<date>/session=<uuid>/manifest.json' \
  --output /tmp/t0-stream-reconciliation.json
```

An interval can legitimately precede the final trade callback in its minute. Every provider update
must therefore match an exact OHLCV prefix that existed no later than the provider observation time;
simple range containment and future-prefix matches are not accepted. Rolling snapshots must also
progress monotonically in provider time, volume, open, high, and low. The report exposes how many
final interval snapshots equal the completed replay bar and reconciles all message, event, session,
and interval counts.

A passed full-session report additionally requires the manifest scope plus both executable trades
and valid quotes to cover every configured symbol, the first executable trade's cumulative volume
to start from the captured quantity, and every executable trade to fall inside an exchange trading
session. Missing minute keys or per-symbol data, non-causal or regressing intervals, volume gaps or
duplicates, incomplete session coverage, or any replay integrity issue returns a failed report and
a non-zero exit code. Quotes and acknowledgements outside the decision sessions remain raw evidence
and are never mistaken for permission to trade.

## Synchronize and certify

The ignored local handoff is `.secrets/dev/t0-trading/ssi.json`. Synchronization validates file
permissions and payload shape, projects only market-data credentials, and writes no values to
Terraform state or command output.

```bash
AWS_PROFILE=tgbao-dev make t0-trading-ssi-secret-sync
AWS_PROFILE=tgbao-dev make t0-trading-certify
```

The certification command reads the managed secret through the standard AWS credential chain and
writes a sanitized, bounded report to `/tmp/mini-lakehouse-t0-certification.json`. It captures field
types, nullability, small public samples, pagination overlap, message counts, and duplicate
fingerprints. SDK exception messages and internal request state are deliberately excluded. The
command writes the report before returning non-zero when any probe is partial, so unresolved
provider behavior remains a visible gate. Generated reports are disposable local evidence and are
not committed.

The versioned `ssi-fastconnect-rest/v1` contract includes one completed trading date of
SDK-auto-paginated stock master data, stock summaries, stock daily and one-minute OHLC, the official
index catalog, and daily index summaries. It deliberately does not claim historical index OHLC:
the generic SDK method accepts index identifiers but the provider returns no bars for that scope.
Curated `trade_date` partitions are derived from each provider record and checked against the bounded
source date; request and processing timestamps never choose the market-data partition.
`index_bars_1m` remains a provider-neutral target for a separately contracted source; no iBoard data
is mislabeled as FastConnect SDK evidence. Bounded stream capture uses the SDK aggregate symbol
subscription for trades, quotes, and foreign-room updates plus the SDK one-minute interval
subscription. Certification separately probes the index stream subscription. Provider interval bars
remain reconciliation evidence; deterministic bars built from captured trades are certified by the
explicit full-session report before any future curated promotion.

## Delivery gates

1. Keep the scheduled REST capture bounded to one SSI-observed completed trading date.
2. Reconcile each full-session capture against its landing and curated counts.
3. Observe disconnect, reconnect, resubscribe,
   ordering, duplicate payloads, and Top-3 completeness behavior.
4. Keep signal generation and order execution disabled until their independent evidence gates pass.

The canonical implementation checklist remains the repository plan during development; this page
documents only behavior that already exists.
