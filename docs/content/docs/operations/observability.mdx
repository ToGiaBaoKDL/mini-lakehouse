## Netdata

Netdata is the primary host, container, PostgreSQL, service-health, certificate, systemd, and
Airflow StatsD view. Its UI is available at `https://netdata.tgblab.io.vn` through Cloudflare
Access and at `http://127.0.0.1:19999` on the services host.

`deploy-netdata.yml` deploys a pinned upstream image and an immutable configuration release. The
runtime validates its persistent mounts, loopback-only UI, bridge-only StatsD listener, native
collectors, PostgreSQL query-function access, Airflow chart contract, and normal Health mode.

The Agent stores three bounded tiers: seven days at full resolution, 90 days at the first
aggregation tier, and one year at the second aggregation tier. Size limits cap each tier before
its time limit.

### Reading native units

- Host CPU is normalized to the whole host and ranges from 0 to 100 percent.
- Container `cpu` is relative to one logical core and can exceed 100 percent; `cpu_limit` is the
  normalized quota or host-capacity view.
- RAM and container memory use MiB; filesystem capacity uses GiB.
- Disk throughput uses KiB/s and network throughput uses kilobits/s. Negative write or transmit
  dimensions indicate chart direction, not negative activity.
- Airflow timers use `ms`. Netdata StatsD emits zero for an idle timer interval, so charts named
  `Observed ... (p95)` should be interpreted only where duration events are present.

External notification channels remain disabled until an owned receiver is configured. Native
Health evaluation, history, and dashboard status remain enabled.

## SigNoz

`deploy-signoz.yml` validates the Foundry casting and lock, validates the Collector image and
configuration, deploys both over Tailscale, then applies dashboards and alerts through Terraform.

The SigNoz UI is available at:

- `https://observe.tgblab.io.vn` through Cloudflare Access;
- `http://tgbao-dev-services:8082` over Tailscale;
- `http://127.0.0.1:8082` on the host.

OTLP ports 4317 and 4318 bind only to host loopback. Applications export through the shared Docker
observability network to the Collector gateway.

## Health checks

1. Check the Collector health endpoint on host loopback port 13133.
2. Inspect `otelcol_*` metrics for receive failures, queue pressure, send failures, process memory,
   and uptime.
3. Check the expected service's telemetry attributes before changing a dashboard query.
4. Treat absent data as a collection-path issue until the producer, receiver, processor, and
   exporter have each been verified.

## Dashboard conventions

- Names use `<domain> / <system>`.
- Number panels state their unit and aggregation in the description.
- CPU cores and CPU percentages are separate signals.
- Histograms use matching duration units before percentile calculation.
- Airflow attributes use `airflow.dag_id` and `airflow.task_id`.
- Backup status is alert-only; it does not have a low-value dashboard.

## Apply dashboards manually

```bash
export AWS_PROFILE=tgbao-dev
export SIGNOZ_ACCESS_TOKEN='<service-account-key>'
make signoz-plan
make signoz-apply
```

Do not edit Terraform-managed dashboards or alerts through the UI.
